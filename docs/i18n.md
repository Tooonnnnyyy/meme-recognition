# Languages: English and 中文

Every page (Usability Lab, the Usability Copilot participant runtime and researcher screens, Gesture Meme Studio) shows its interface in English or Simplified Chinese.

- **Auto** (default) follows the system: the first of English or Chinese in the browser's language list, which follows the operating system unless the person changed it. Anything else falls back to English.
- **EN / 中文** pins a language. The choice is saved in this browser (`localStorage` key `lang`) and applies to every page of the site, like the colour theme.
- **Participants** see the study's language. The researcher picks it on the study's Plan tab (it defaults to the researcher's interface language when the study is created), because the consent form, the questionnaires and the task wording are one research instrument. A participant can still switch between English and 中文 for that visit; the switch is not saved.

## What is translated

- All interface text, messages and errors.
- Generated documents: the consent form draft and the data-management statement use the **study's** language; the report's Markdown export uses the **reader's** interface language.
- CSV exports keep English column names and codes (`section`, `task`, `success`…), so analysis scripts work whatever language the researcher reads. Notes and quotes stay as they were typed.
- Researcher-written content (study title, task instructions, notes) is never machine-translated.
- The demo shop's pages are in English. The Chinese demo tasks name the English items they point at.

## Questionnaires in Chinese

The SEQ, SUS and UMUX-Lite are standardised instruments. The Chinese wording here follows the SUS translation in common use; it is **not** the psychometrically validated revision by Wang, Lei and Liu (2019, *International Journal of Human–Computer Interaction*, doi:10.1080/10447318.2019.1700644). For work you intend to publish, check the wording against that paper. To stay comparable:

- Each session records the languages its questionnaires were answered in (`questionnaireLangs`).
- The report warns when a study mixes languages, because scores from different language versions are not interchangeable without validation.

## For developers

- Messages live in `src/i18n/messages/<namespace>.js` as `{ en: {...}, zh: {...} }` and are looked up as `namespace.key`. Keys must match in both languages, with the same `{placeholders}`. `tests/i18n.test.js` checks this and fails on English text left in the markup.
- In components: `const t = useT()`, then `t('lab.newStudy')` or `t('report.participants', { count })`. `t.lang` is the current language. For a sentence with a link or bold part, use `<Rich text={t('…')} tags={{ link: text => <a href="…">{text}</a> }} />`.
- In modules without React: take a `lang` argument (default `'en'`, which keeps tests and old callers working) and call `translate(lang, key, vars)`. Throw `new TextError(key, vars)` for errors a screen shows; the screen renders `errorText(t, error)`.
- A message can be a function of its variables when grammar needs it, such as English plurals: `tasks: ({ count }) => (count === 1 ? '1 task' : `${count} tasks`)`. Chinese usually needs no plural form: `tasks: '{count} 个任务'`.
- Numbers and dates: `formatNumber(lang, value, options)` and `formatDate(lang, value, options)`.
